# qupath-fov-export

用 QuPath 0.7 批量导出**固定尺寸、固定放大倍数**的视野（FOV）。

在切片上手工摆好选框后，一条命令把所有框导成图片：尺寸严格一致、文件名带坐标与分辨率、
附一份 CSV 清单。全程无头，也可以直接在脚本编辑器里跑。

## 为什么需要这个

QuPath 自带的导出（`Export image region…` / `Original pixels…`）**一次只能导一个区域**。
选中多个框再导，得到的是它们外接框合成的**一张**大图——不是每个框一个文件。

另外，导出尺寸和放大倍数是两个容易混淆的量：

```
输出像素宽 = round(区域像素宽 / downsample)
区域像素宽 = 物理宽度(µm) / 每像素微米(MPP)
等效物镜倍数 ≈ 10 / (MPP × downsample)
```

**downsample 不改变视野范围**，只决定这块范围用多少像素表示。想同时锁定"放大倍数"和"输出像素数"，
视野大小就被唯一确定了，没有第三个自由度。

以 MPP = 0.10 µm/px 的切片、4000 px 的框为例：

| downsample | 导出后 µm/px | 等效倍数 | 输出 | 物理视野 |
|---:|---:|---:|---:|---:|
| 1 | 0.100 | ~100x | 4000 px | 400 µm |
| 2 | 0.200 | ~50x | 2000 px | 400 µm |
| 2.5 | 0.250 | 40x | 1600 px | 400 µm |
| 4 | 0.400 | ~25x | 1000 px | 400 µm |

想要"40x **且** 2000 px 输出"，就得把框改成 5000 px（= 500 µm 见方）。

## 快速开始

**GUI**：把 `scripts/export_fovs.groovy` 放进项目的 `scripts/` 目录（或直接拖进 QuPath 窗口），
`Automate ▸ Script editor` 打开，改好开头参数，Run。只对当前打开的图像生效。

**命令行**（整个项目批量）：

```bash
QP=<QuPath 可执行文件>

# 用脚本开头的默认参数
"$QP" script -p /abs/项目/project.qpproj -s scripts/export_fovs.groovy

# 临时覆盖 --args "[downsample, 框边长px, 输出目录, 额外倍数(可选,分号隔开)]"
"$QP" script -p /abs/项目/project.qpproj -s scripts/export_fovs.groovy \
  --args "[2.0, 4000, /abs/输出目录]"

# 一次出两套倍数：主倍数 2.0 + 额外 4.8345（20x）
"$QP" script -p /abs/项目/project.qpproj -s scripts/export_fovs.groovy \
  --args "[2.0, 4000, /abs/输出目录, 4.8345]"
```

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `DOWNSAMPLE` | 2.0 | 导出降采样倍数 |
| `EXTRA_DOWNSAMPLES` | `[]` | 同一个框额外再导的倍数，例如 `[4.8345]` 就同时出一套 20x |
| `BOX_PX` | 4000 | 只导这个边长的正方形框；填 0 = 导所有非整图标注 |
| `OUT_DIR` | `~/Downloads/QuPath_FOV` | 输出目录，不存在会自动新建，已存在就直接用 |
| `EXT` | `tif` | `tif` / `png` / `jpg` |
| `TIFF_COMPRESSION` | `LZW` | 仅对 tif 生效：`LZW` / `Deflate` / `None` |
| `WRITE_MANIFEST` | true | 是否写 CSV 清单 |

## 一个视野出多个倍数（比如 40x + 20x）

**倍数由 `downsample` 决定，不是由框的大小决定。** 同一个框用不同 downsample 各导一份，
得到的就是同一视野的不同分辨率版本。设 `EXTRA_DOWNSAMPLES = [4.8345]`，一次跑完两套：

```
== 片名  mpp=0.1034  框 4000 px (视野 414 um)
   倍数 ds=2.0     -> 48.3x  0.2068 um/px  输出 2000 px
   倍数 ds=4.8345  -> 20.0x  0.5000 um/px  输出 827 px
   fov1  ds=2.0     -> 2000x2000 px  0.207 um/px
   fov1  ds=4.8345  ->  827x827  px  0.500 um/px
   合计 6 张（3 个框 × 2 个倍数），用时 1.7 秒
```

两套文件名靠 µm/px 区分（`..._0.207umpp.tif` / `..._0.500umpp.tif`），清单里有 `downsample` 列。

各倍数对应的数字（MPP 0.1034 µm/px 时）：

| 目标 | µm/px | downsample | 2000 px 输出需要的框 | 该框的视野 |
|---|---:|---:|---:|---:|
| ~100x（原生层） | 0.103 | 1 | 2000 px | 207 µm |
| ~48x（原生层） | 0.207 | 2 | 4000 px | 414 µm |
| 40x | 0.250 | 2.417 | 4835 px | 500 µm |
| ~24x（原生层） | 0.414 | 4 | 8000 px | 827 µm |
| 20x | 0.500 | 4.8345 | 9670 px | 1000 µm |

通用公式：

```
downsample = 目标µm每像素 / MPP
框边长     = 输出像素数 × downsample
```

downsample 取 1/2/4/8/16… 时正好命中原生金字塔层，最锐也最快；其它值会从最近一层插值，略软但通常看不出来。

**如果两个倍数想要不同的取景范围**（20x 当概览、40x 看局部细节），那就摆两套不同大小的框，
分两次跑脚本（`BOX_PX` 各填一次），输出到不同目录。这种情况不适合一次导出。

## 关键设计：按尺寸筛选框

脚本只导**边长等于 `BOX_PX`** 的框。这样：

- 项目里本来就有的组织标注（往往覆盖整张切片，几万×几万像素）自动排除，不会把内存吃爆
- 尺寸不统一的框也排除，**保证所有导出的视野严格同尺寸**——组间比较的前提
- **被跳过的标注会逐个列出来并标出实际尺寸**，不会静默少导。画错一个框（比如误拖成 3999 px）
  会在控制台直接看到，而不是等你发现少了一张图
- 一个都没匹配上时同样报告，便于排查

框的数量**没有上限**：找到几个导几个，一次读一块区域，内存占用与框的数量无关。
实测 5 个框 2.3 秒（含 JVM 和项目启动）。

排序按从上到下、从左到右，所以 `fov1/2/3…N` 的编号在不同切片上是一致的（按位置，不按摆框先后）。

## 输出

- 文件名：`<片名>_fov<N>_x<x>_y<y>_<µm每像素>umpp.tif`
- 清单：`fov_manifest.csv`，记录片名、序号、坐标、框大小、视野 µm、downsample、µm/px、文件名
- 清单按片子去重：同一张片子重新导出会替换旧记录，其它片子的记录保留

## 体积（同一块 2000×2000 区域实测）

| 写法 | 体积 | 耗时 | 无损 |
|---|---:|---:|:--:|
| `.tif`（QuPath 默认，不压缩） | 11.44 MB | 37 ms | 是 |
| `.tif` + LZW | 2.30 MB | 194 ms | 是 |
| `.tif` + Deflate | 1.45 MB | 737 ms | 是 |
| `.png` | 1.68 MB | 138 ms | 是 |
| `.jpg` | 0.14 MB | 54 ms | **否** |

QuPath 自己的 `.tif` 写法是**完全不压缩**的，45 张就能到 500 MB 以上，所以脚本自己控制压缩，
默认 LZW（无损，兼容性最好）。嫌大就换 `Deflate`；要跟别人的软件交换文件时 LZW 更保险。

## 坑

- `--args "[2.0, 4000, /path]"` 里**逗号后的空格会被保留**，不 trim 的话输出目录会变成以空格
  开头的相对路径，文件全跑到奇怪的地方。脚本已处理，自己写脚本时注意。
- 输出尺寸是 `round(区域 / downsample)`，区域不是 downsample 整数倍时可能差 1 px。
  想严格等于目标值，让框边长是 downsample 的整数倍。
- `BOX_PX` 填 0 会导所有非整图标注，包括组织标注——注意后果。
- 脚本**不会**加比例尺：QuPath 的比例尺只是屏幕上的显示元素，不会写进导出文件。
  做图时在排版软件里加（独立图层，还能统一整组样式）。
- 同名文件**直接覆盖**。想同时保留多套参数的结果，就把输出目录分开。

## 验收

1. 控制台打印的框数量 = 你摆的框数量
2. 每张输出尺寸 = `round(BOX_PX / DOWNSAMPLE)`，且所有文件尺寸一致
3. 打开一张图，确认位置正确、不是整张切片
4. `fov_manifest.csv` 行数 = 图片数，坐标与图上一致
