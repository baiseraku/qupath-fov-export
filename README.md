# qupath-fov-export

用 QuPath 0.7 批量导出**固定尺寸、固定放大倍数**的视野（FOV）。

在切片上手工摆好选框后，一条命令把所有框导成图片：尺寸严格一致、文件名带坐标与分辨率、
附一份 CSV 清单。全程无头，也可以直接在脚本编辑器里跑。

## 为什么需要这个

QuPath 自带的导出（`Export image region…` / `Original pixels…`）**一次只能导一个区域**。
选中多个框再导，得到的是它们外接框合成的**一张**大图——不是每个框一个文件。

另外，导出尺寸和放大倍数是两个容易混淆的量：

```
输出像素宽 = round(区域像素宽 / downsample)
区域像素宽 = 物理宽度(µm) / 每像素微米(MPP)
等效物镜倍数 ≈ 10 / (MPP × downsample)
```

**downsample 不改变视野范围**，只决定这块范围用多少像素表示。想同时锁定"放大倍数"和"输出像素数"，
视野大小就被唯一确定了，没有第三个自由度。

以 MPP = 0.10 µm/px 的切片、4000 px 的框为例：

| downsample | 导出后 µm/px | 等效倍数 | 输出 | 物理视野 |
|---:|---:|---:|---:|---:|
| 1 | 0.100 | ~100x | 4000 px | 400 µm |
| 2 | 0.200 | ~50x | 2000 px | 400 µm |
| 2.5 | 0.250 | 40x | 1600 px | 400 µm |
| 4 | 0.400 | ~25x | 1000 px | 400 µm |

想要"40x **且** 2000 px 输出"，就得把框改成 5000 px（= 500 µm 见方）。

## 快速开始

**GUI**：把 `scripts/export_fovs.groovy` 放进项目的 `scripts/` 目录（或直接拖进 QuPath 窗口），
`Automate ▸ Script editor` 打开，改好开头参数，Run。只对当前打开的图像生效。

**命令行**（整个项目批量）：

```bash
QP=<QuPath 可执行文件>

# 用脚本开头的默认参数
"$QP" script -p /abs/项目/project.qpproj -s scripts/export_fovs.groovy

# 临时覆盖 --args "[框边长(分号隔开), 输出边长px, 输出目录, 额外输出边长(可选,分号隔开)]"
"$QP" script -p /abs/项目/project.qpproj -s scripts/export_fovs.groovy \
  --args "[4000, 2000, /abs/输出目录]"

# 混搭：4000 的框按 ds=2 导、8000 的框按 ds=4 导，出来的图都是 2000x2000
"$QP" script -p /abs/项目/project.qpproj -s scripts/export_fovs.groovy \
  --args "[4000;8000, 2000, /abs/输出目录]"
```

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `BOX_SIZES` | `[4000, 8000]` | 允许的框边长（px），可写多个；`[]` = 导所有非整图标注 |
| `OUT_PX` | 2000 | 目标输出边长（px）。downsample 自动 = 框边长 / OUT_PX |
| `EXTRA_OUT_PX` | `[]` | 同一个框额外再导的输出尺寸，如 `[1000]` 再多一套小图 |
| `OUT_DIR` | `~/Downloads/QuPath_FOV` | 输出目录，不存在会自动新建，已存在就直接用 |
| `EXT` | `tif` | `tif` / `png` / `jpg` |
| `TIFF_COMPRESSION` | `LZW` | 仅对 tif 生效：`LZW` / `Deflate` / `None` |
| `WRITE_MANIFEST` | true | 是否写 CSV 清单 |

## 倍率自动算：你只填"图要多大"

**导出倍率由框的大小决定，不用手填 downsample。**

```
downsample = 框边长 / OUT_PX
```

所以多大框出来的图都是 `OUT_PX` 见方。下面这次是 5 个 4000 px 的框 + 2 个 8000 px 的框，
一次导完，全部 2000×2000：

```
== 片名  mpp=0.1034  输出统一 2000 px  格式 tif (LZW)
   4000px    5 个框  视野 414 um  ds=2.0000  ->  48.3x  0.2068 um/px
   8000px    2 个框  视野 827 um  ds=4.0000  ->  24.2x  0.4137 um/px
   4000px   fov1   ds=2.0000   视野  414 um -> 2000x2000 px  0.207 um/px
   ...
   8000px   fov1   ds=4.0000   视野  827 um -> 2000x2000 px  0.414 um/px
   合计 7 张（7 个框 × 1 个输出尺寸），用时 2.9 秒
```

**面积 4 倍 = 边长 2 倍**。所以"比 40x 视野大 4 倍、导出还要 2000×2000"就是框边长翻一倍
（4000 → 8000），倍率自动跟着翻一倍（ds 2 → 4），等效倍数减半（48x → 24x）。

几点说明：

- **编号在各自尺寸组内独立**（`4000px_fov1`、`8000px_fov1`），这样同一组在不同片子间才对得齐
- 文件名里带框尺寸，一眼能分出哪张是概览、哪张是细节
- downsample 取整数次幂（1/2/4/8…）时正好命中原生金字塔层，最锐也最快
- 框比 `OUT_PX` 还小时会按 ds=1 处理，不会放大

想同时出多个输出尺寸就填 `EXTRA_OUT_PX`（比如 `[1000]`），每个框各导一套。

各倍数对应的框边长（MPP 0.1034 µm/px、输出 2000 px 时）：

| 目标 | µm/px | downsample | 框边长 | 视野 |
|---|---:|---:|---:|---:|
| ~100x（原生层） | 0.103 | 1 | 2000 px | 207 µm |
| ~48x（原生层） | 0.207 | 2 | 4000 px | 414 µm |
| 40x | 0.250 | 2.417 | 4835 px | 500 µm |
| ~24x（原生层） | 0.414 | 4 | 8000 px | 827 µm |
| 20x | 0.500 | 4.8345 | 9670 px | 1000 µm |

换个 MPP 就按 `框边长 = OUT_PX × 目标µm每像素 / MPP` 重算。

**想让代表图和细节图同心**（大图 + 方框标出放大区域）：新 X = 旧 X − 旧框边长 ×(k−1)/2，
k 是边长放大倍数。比如 4000 的框在 (5000, 5000)，翻倍后填 **X=3000, Y=3000, Width=8000, Height=8000**。

## 关键设计：只导指定尺寸的框

只有边长命中 `BOX_SIZES` 的框会被导出。这样：

- 项目里本来就有的组织标注（往往覆盖整张切片，几万×几万像素）自动排除，不会把内存吃爆
- 多个尺寸可以混着一次导完，各自用各自的倍率
- **被跳过的标注会逐个列出来并标出实际尺寸**，不会静默少导。画错一个框（比如误拖成 3999 px）
  会在控制台直接看到，而不是等你发现少了一张图
- 一个都没匹配上时同样报告，便于排查

框的数量**没有上限**：找到几个导几个，一次读一块区域，内存占用与框的数量无关。

排序：先按尺寸分组，组内从上到下、从左到右。所以 `4000px_fov1` 在不同切片上指的是同一个位置
（按位置排，不按摆框先后）。

## 输出

- 文件名：`<片名>_<框尺寸>px_fov<N>_x<x>_y<y>_<µm每像素>umpp.tif`
- 清单：`fov_manifest.csv`，列为
  `slide, group, fov, x, y, box_px, out_px, downsample, um_per_px, field_um, file`
- 清单按片子去重：同一张片子重新导出会替换旧记录，其它片子的记录保留

## 体积（同一块 2000×2000 区域实测）

| 写法 | 体积 | 耗时 | 无损 |
|---|---:|---:|:--:|
| `.tif`（QuPath 默认，不压缩） | 11.44 MB | 37 ms | 是 |
| `.tif` + LZW | 2.30 MB | 194 ms | 是 |
| `.tif` + Deflate | 1.45 MB | 737 ms | 是 |
| `.png` | 1.68 MB | 138 ms | 是 |
| `.jpg` | 0.14 MB | 54 ms | **否** |

QuPath 自己的 `.tif` 写法是**完全不压缩**的，45 张就能到 500 MB 以上，所以脚本自己控制压缩，
默认 LZW（无损，兼容性最好）。嫌大就换 `Deflate`；要跟别人的软件交换文件时 LZW 更保险。

## 坑

- `--args "[4000;8000, 2000, /path]"` 里**逗号后的空格会被保留**，不 trim 的话输出目录会变成以空格
  开头的相对路径，文件全跑到奇怪的地方。脚本已处理，自己写脚本时注意。
- 框边长不是 `OUT_PX` 的整数倍时（比如 4835 的框要导 2000 px），downsample 会是小数（2.4175），
  输出尺寸仍**严格**等于 `OUT_PX`，但会从最近的金字塔层插值，略软。
- `BOX_SIZES` 填 `[]` 会导所有非整图标注，包括组织标注——注意后果。
- 脚本**不会**加比例尺：QuPath 的比例尺只是屏幕上的显示元素，不会写进导出文件。
  做图时在排版软件里加（独立图层，还能统一整组样式）。
- 同名文件**直接覆盖**。想同时保留多套参数的结果，就把输出目录分开。

## 验收

1. 控制台每个尺寸组报告的框数量 = 你实际摆的数量
2. 所有输出尺寸一致，且等于 `OUT_PX`
3. 打开一张图，确认位置正确、不是整张切片
4. `fov_manifest.csv` 行数 = 图片数，坐标与图上一致
